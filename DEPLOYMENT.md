# FoodConnect production deployment (Render)

## Important

The repository is prepared for Render, but deployment is not performed by this source package. You must authorize the GitHub repository and Render service from your own accounts. Never put account passwords, API tokens, or secret keys in this project or chat.

The included `render.yaml` provisions:
- a Render web service (Starter plan),
- a managed PostgreSQL database (Basic plan),
- a 1 GB persistent disk mounted at `/var/data` for uploaded photos,
- a generated `SECRET_KEY`,
- production cookie security and an admin-email setting.

These Render resources may incur charges. Review the current pricing in your Render dashboard before creating them. A persistent disk is important because the web service's temporary filesystem is not suitable for permanent user uploads.

## Deploy steps

1. Push this project to a GitHub repository. Do not commit `.env`, local databases, uploaded user files, or credentials.
2. In Render, choose **New + → Blueprint** and connect the repository.
3. Review the resources and costs described by `render.yaml`, then approve creation.
4. Set `ADMIN_EMAIL` to the email address of the verified FoodConnect admin account. Optionally set `EMAIL_ADDRESS` and `EMAIL_APP_PASSWORD` if OTP email delivery is desired.
5. Wait for the build and deploy to finish. Inspect the Render logs for database connection or migration errors.
6. Open the Render service URL and test homepage, signup/OTP, login, restaurant detail, review upload, menu, API and admin PDF report.

## Environment variables

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Render PostgreSQL connection string; local fallback is SQLite |
| `SECRET_KEY` | Generated by Render; required in production |
| `UPLOAD_FOLDER` | Persistent upload directory; Render disk path is `/var/data/uploads` |
| `COOKIE_SECURE` | Set to `1` when served over HTTPS |
| `ADMIN_EMAIL` | Verified account email allowed to view reports |
| `EMAIL_ADDRESS` | Optional Gmail sender for OTP |
| `EMAIL_APP_PASSWORD` | Optional Gmail app password; do not commit it |

## Local setup

```bash
python -m venv venv
# Windows: venv\\Scripts\\activate
# macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
copy .env.example .env
python seed_data.py
python app.py
```

For local development, OTP is printed in the terminal if SMTP variables are not configured.

## Persistent uploads

Uploaded review and food photos are served through `/uploads/<filename>`. On Render, the persistent disk must be mounted at `/var/data` and `UPLOAD_FOLDER=/var/data/uploads` must be present. Existing local uploaded files are not included in the distributable ZIP; copy any photos you need to preserve into the persistent disk after deployment.

## Limitations

- The included sample restaurant names, addresses, coordinates, menu items and prices are illustrative university-demo data, not verified business listings.
- The sentiment classifier uses an explainable lexical baseline unless a compatible `.tflite` model and vocabulary are supplied.
- Maps use OpenStreetMap and YouTube embeds require valid public video URLs.
- Test the live service after deployment; a successful build alone does not prove all user journeys work.
